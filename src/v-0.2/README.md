# DataCenter Thermal Digital Twin — v0.2

**Purpose:** ingest the public Aalborg University server-room dataset, inspect its workbook/geometry metadata, build a reviewed sensor-to-XYZ mapping, and render measured temperatures at their actual measurement locations in an interactive 3D plot.

> Research prototype only. The Aalborg room is not Visionbay/亞灣算力中心. Do not describe its measurements as Visionbay measurements. A sensor's XYZ location is only considered verified when it is sourced from the dataset's official geometry/layout or reviewed against the drawing.

## What's new in v0.2

- Zenodo API-based dataset discovery and selective downloads.
- Workbook and CSV schema inspection (chunked; does not load the 706 MB CSV into RAM).
- Sensor/measurement-port mapping report from the official layout workbook.
- XYZ mapping template and validation workflow.
- Optional DXF entity extraction if the DWG is converted to DXF with ODA File Converter.
- Interactive 3D measured-point temperature view, with time selection and sensor labels.
- Explicit distinction between measured points and interpolated surfaces (no invented coordinates).

## 1. Dataset source

The latest record discovered during preparation is:
- Zenodo record: `21262042` (2026-09 record; includes load-scenario files)
- Previous stable public record: `19398358` (v4, 2026-06)

Record pages:
- https://zenodo.org/records/21262042
- https://zenodo.org/records/19398358

The Zenodo record metadata can change. The downloader queries the record API at run time and selects relevant files by filename. It does not assume that every version uses identical names.

## 2. Install (Manjaro/Linux)

Use a project-specific environment; do not modify your Ricci/TeXmacs environments.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Python 3.11/3.12 is recommended for broad scientific-package wheel availability. Python 3.14 may work, but package compatibility should be checked separately.

## 3. Download dataset files

```bash
python -m src.download_dataset --record 21262042 --dest data
```

This selectively downloads files whose names suggest temperature/power, air speed, supplementary ventilation/temperature, layout, geometry, or measurement visualization. It does not download unrelated files. The main measurement CSV may be hundreds of MB.

If the latest record ID is unavailable, try:
```bash
python -m src.download_dataset --record 19398358 --dest data
```

To see available files without downloading:
```bash
python -m src.download_dataset --record 21262042 --dest data --list-only
```

## 4. Inspect all downloaded metadata

```bash
python -m src.inspect_dataset --data-dir data --out outputs/inspection
```

This creates:
- `csv_schema_report.json`
- `excel_workbook_report.json`
- `sensor_mapping_candidates.csv`
- `sensor_xyz_template.csv`

The script samples CSVs in chunks and reports workbook sheets/columns. It does not claim an XYZ mapping unless XYZ fields are actually present in the workbook.

## 5. Build / review the sensor XYZ map

Open `outputs/inspection/sensor_xyz_template.csv`.

Fill `x_m,y_m,z_m` using the official drawing/layout coordinate system. Preserve `sensor_id` and `measurement_port` exactly. If the workbook already contains coordinate columns, candidates are prefilled.

Important:
- Confirm units (m, mm, or drawing units) before converting.
- Confirm origin and axis orientation from the official drawing.
- Do not estimate sensor coordinates from a screenshot without scale/control points.
- Keep `coordinate_source` and `review_status` populated.
- A mapping row should be marked `verified` only after checking the official drawing.

Optional DWG workflow:
1. Install ODA File Converter from the Open Design Alliance (if available for your Linux setup).
2. Convert `AAU_DC_geometry_with_measurement_points.dwg` to DXF.
3. Run:
   ```bash
   python -m src.extract_dxf_labels data/AAU_DC_geometry_with_measurement_points.dxf \
       --out outputs/dxf_entities.csv
   ```
4. Use the extracted text/point/block labels to reconcile sensor IDs. DXF entity extraction is a helper, not automatic semantic identification.

## 6. Run the 3D viewer

```bash
streamlit run app.py
```

In the sidebar:
- choose the temperature/power CSV;
- choose timestamp and temperature fields;
- choose a sensor ID field if the CSV is long-form;
- load `sensor_xyz_template.csv` after completing its coordinates;
- choose a timestamp (or nearest available time).

The 3D plot shows **measured sensor locations only**. A continuous interpolated surface is not generated by default because sparse sensors do not justify treating every voxel as measured. A later version can add explicitly labelled interpolation/uncertainty.

## 7. Data format support

The loader supports:
- long form: timestamp, sensor/measurement-point ID, temperature;
- wide form: timestamp plus one column per sensor.

The app uses a bounded row sample for responsive preview. For very large CSVs, preprocess a time window with the chunked utility rather than loading the entire dataset into Streamlit.

## 8. Research quality controls

Before interpreting any plot:
1. Read the Zenodo README/record description and workbook.
2. Confirm each column's physical meaning and units.
3. Confirm time zone and timestamp format.
4. Confirm whether values are raw, averaged, filtered or resampled.
5. Verify sensor ID-to-coordinate mapping and coordinate reference.
6. Use chronological holdout for forecasting.
7. Report only observed measurement points as measurements.
8. Keep the Aalborg benchmark separate from any future Visionbay site model.

## 10. Limitations

- Dataset metadata and filenames may change; downloader uses API metadata but still requires human review.
- DWG is a CAD format; Python libraries do not reliably parse all DWG variants directly. Convert to DXF for entity extraction.
- The layout workbook may describe port/sensor relationships without storing full XYZ coordinates. If so, coordinates must be reconciled against the drawing.
- The first 3D view is a point cloud of measured values, not CFD and not a complete volumetric temperature field.
- No facility controls are connected or actuated.
